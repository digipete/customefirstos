# Architecture

Making structural choices that keep future options open.

## Why we do this

Architecture shapes decisions that are expensive to reverse later, so the practice is held to a shared standard across every mission.

## What this means for us

Architecture works inside the squad from the start of a mission, contributes hypotheses and evidence, and updates this guidance when missions show it is wrong.

## Good looks like

- involved from Discovery, not invited at Deliver
- opinions expressed as testable hypotheses
- standards applied consistently across missions
- learning written back to the pattern library

## Anti-patterns

- Architecture as a review gate at the end
- standards that exist only in one person's head
